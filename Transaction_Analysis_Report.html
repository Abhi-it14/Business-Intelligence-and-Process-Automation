Number of Transactions, Category-Wise

Note on IFT: The dataset contains 89 IFT (Internal Funds Transfer) transactions. Since the assignment brief specifies UPI, IMPS, RTGS, and NEFT only, IFT is excluded from this answer but is included in the channel overview table above.

SQL Query

SELECT  Narration           AS Category,
        COUNT(*)            AS No_Of_Transactions
FROM    transactions
WHERE   Narration IN ('UPI', 'IMPS', 'RTGS', 'NEFT')
GROUP BY Narration
ORDER BY No_Of_Transactions DESC;

Monthly Cohort View of Active Users (DEBIT)

A user's cohort is the month of their first DEBIT transaction. Each cell shows how many distinct users from that cohort made at least one DEBIT transaction in the given activity month.

SQL Query

WITH debit_txns AS (
    SELECT User_Id,
           strftime('%Y-%m', Transaction_Time) AS Txn_Month
    FROM   transactions
    WHERE  Transaction_Type = 'DEBIT'
),
cohort AS (
    SELECT User_Id, MIN(Txn_Month) AS Cohort_Month
    FROM   debit_txns GROUP BY User_Id
),
activity AS (
    SELECT DISTINCT d.User_Id, d.Txn_Month, c.Cohort_Month
    FROM   debit_txns d JOIN cohort c ON d.User_Id = c.User_Id
)
SELECT Cohort_Month,
       Txn_Month        AS Active_Month,
       COUNT(DISTINCT User_Id) AS Active_Users
FROM   activity
GROUP BY Cohort_Month, Txn_Month
ORDER BY Cohort_Month, Txn_Month;

Top 10 Percentile Users by Net Amount (DEBIT − CREDIT)

Net Amount = Total DEBIT − Total CREDIT for each user. The top 10 percentile means PERCENT_RANK() ≥ 0.90. With only 10 users, this isolates the single user with the least-negative (highest) net amount.

SQL Query

WITH user_net AS (
    SELECT User_Id,
           SUM(CASE WHEN Transaction_Type = 'DEBIT'
                    THEN  Transaction_Amt ELSE 0 END) AS Total_Debit,
           SUM(CASE WHEN Transaction_Type = 'CREDIT'
                    THEN  Transaction_Amt ELSE 0 END) AS Total_Credit,
           SUM(CASE WHEN Transaction_Type = 'DEBIT'
                    THEN  Transaction_Amt
                    ELSE -Transaction_Amt END)   AS Net_Amount
    FROM   transactions GROUP BY User_Id
),
ranked AS (
    SELECT User_Id, Total_Debit, Total_Credit, Net_Amount,
           PERCENT_RANK() OVER (ORDER BY Net_Amount) AS Pct_Rank
    FROM   user_net
)
SELECT User_Id, Total_Debit, Total_Credit, Net_Amount
FROM   ranked
WHERE  Pct_Rank >= 0.90
ORDER BY Net_Amount DESC;

Limitations & Assumptions

  • "Load amount" assumption: Interpreted as the amount of CREDIT transactions. The dataset has no explicit "load amount" column. This assumption is stated clearly throughout Q3.
  • IFT channel: 89 IFT transactions exist in the dataset but are not included in Q2 results, as the brief specifies only UPI, IMPS, RTGS, NEFT.
  • Small user base: With only 10 users, the top 10 percentile collapses to a single user (Q5). Statistical distributions and cohort patterns should be interpreted with this small sample size in mind.
  • Date parsing: Dates are in M/D/YYYY format; SQLite's strftime() requires ISO format. In Q4, the Month column (integer 1–7) was used directly for grouping to avoid date-parsing edge cases.
  • No deduplication needed: Txn_id values were verified to be unique across all 501 records.
  • Currency: All amounts are assumed to be in Indian Rupees (₹). No currency column exists in the dataset.
